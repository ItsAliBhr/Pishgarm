# ۵. اسناد، قالب‌ها و فایل‌ها

## ۵.۱ قالب‌ها

همه‌ی قالب‌ها فایل Word با نحو **docxtpl** (Jinja2) هستند. از اسناد واقعی شرکت ساخته شده‌اند، پس ظاهر خروجی همان ظاهر همیشگی است. خروجی درست هر قالب در `templates/previews/*.pdf` است. این پیش‌نمایش‌ها با LibreOffice و فونت جایگزین ساخته شده‌اند. در Word با فونت B Nazanin، چیدمان دقیق‌تر است.

| قالب | کاربرد | صفحه |
|---|---|---|
| `letter_company.docx` | نامه با سربرگ شرکت (پس‌زمینه در Header، کادر تاریخ، شماره و پیوست، مهر و امضا) | A4 عمودی |
| `letter_personal.docx` | نامه‌ی شخصی (باسمه تعالی، بدون سربرگ) | A4 عمودی |
| `proforma_company.docx` | پیش‌فاکتور، فاکتور و صورت‌وضعیت با سربرگ | A4 افقی |
| `proforma_personal.docx` | پیش‌فاکتور، فاکتور و صورت‌وضعیت شخصی، با بخش‌های پرداخت، حمل، سایر و توضیحات | Letter افقی |
| `attachment_list.docx` | پیوست «لیست اقلام» (قرمز برای اقلام تأمین خریدار) | A4 عمودی |

برچسب‌های ویژه‌ی docxtpl که در قالب‌ها به کار رفته‌اند:
- `{%p … %}`: حلقه یا شرط روی پاراگراف
- `{%tr … %}`: حلقه یا شرط روی ردیف جدول
- `{% if show_stamp %}…{% endif %}`: دور run تصویر مهر و امضا

**قاعده:** برنامه هرگز متن ثابت قالب را تولید نمی‌کند. همه‌ی متن‌های متغیر از context می‌آیند. برای عوض کردن ظاهر، فقط فایل قالب در Word ویرایش می‌شود، با حفظ برچسب‌ها. اسکریپت‌های ساخت قالب در `tools/template_builders/` هستند.

## ۵.۲ قرارداد context

### نامه (`letter_*.docx`)
```json
{
  "header_line": "باسمه تعالی",            // فقط شخصی؛ خالی = حذف
  "date": "1405/09/01", "number": "012/1405", "attachment": "ندارد",
  "addressee_lines": ["شرکت صنایع آهن و فولاد سرمد ابرکوه", "جناب آقای مهندس شهسواری"],
  "subject": "درخواست آزادسازی سپرده‌ی حسن انجام کار",   // خالی = بدون خط موضوع
  "salutation": "با سلام و احترام؛",
  "body_paragraphs": ["…", "…"],          // همه‌ی متن، شامل فهرست شماره‌دار «1- …» و بندهای انتخابی
  "closing": "با تشکر", "signer_name": "بهرامی", "signer_title": "",
  "show_stamp": true, "show_signature": true,   // قالب شرکتی
  "signature_image": null                       // قالب شخصی: InlineImage یا null
}
```

### پیش‌فاکتور، فاکتور و صورت‌وضعیت (`proforma_*.docx`)
```json
{
  "title": "پیش‌فاکتور فروش و خدمات",     // یا «فاکتور فروش و خدمات» / «صورت وضعیت»
  "date": "1405/09/01", "number": "014/1405",
  "seller": {"name","address","postal_code","national_id","economic_code","registration_no","phone","fax"},
  "buyer":  {…همان کلیدها…},
  "items": [{"idx":1,"description":"…","unit":"عدد","qty":"2","unit_price":"3,500,000,000","total":"7,000,000,000"}],
  "totals": {"vat_enabled":true,"subtotal":"…","subtotal_words":"…","vat_percent":"10","vat":"…",
             "payable_label":"قابل پرداخت","payable":"…","payable_words":"… ریال"},
  // قالب شرکتی: یک فهرست شماره‌دار
  "clauses": ["…","…"],
  // قالب شخصی: چهار گروه جدا
  "payment_clauses": [], "delivery_clauses": [], "other_clauses": [], "note_clauses": [],
  "closing": "با احترام", "signer_name": "بهرامی", "show_stamp": true, "show_signature": true
}
```
- همه‌ی عددها به‌صورت **رشته‌ی قالب‌بندی‌شده** پاس داده می‌شوند. قالب حساب نمی‌کند.
- تعداد اعشاری مجاز است (مثلاً `40655` کیلوگرم یا `2.5` تن).
- `payable_label` وقتی ارزش افزوده خاموش است «جمع کل» و وقتی روشن است «قابل پرداخت» است.
- **نگاشت گروه‌ها در قالب شخصی:**
  - `payment` ← payment_clauses
  - `delivery` ← delivery_clauses
  - `tax` + `site` + `other` ← other_clauses
  - `note` ← note_clauses
- **قالب شرکتی:** همه‌ی بندها به همین ترتیب پشت سر هم می‌آیند و بند حساب آخر قرار می‌گیرد.

### لیست اقلام (`attachment_list.docx`)
```json
{"title":"لیست اقلام …","subtitle":"17 مشعل",
 "items":[{"idx":1,"description":"…","qty":"4","unit":"عدد","buyer_supplied":false,"emphasis":true}],
 "footer_note":"اقلامی که با رنگ دیگر مشخص شده است توسط خریدار تأمین می‌گردد."}
```
`footer_note` فقط وقتی پر می‌شود که دست‌کم یک قلم `buyer_supplied` باشد.

نمونه‌ی کامل هر context در `templates/test_contexts/` است. تست رندر باید با همین‌ها اجرا شود.

## ۵.۳ ساخت متن نامه

1. `addressee_lines` از سه جزء ساخته می‌شود:
   - نام کامل شرکت
   - «{position} محترم» اگر سمت داشت
   - «{title_prefix} {honorific} {name}»، مثل «جناب آقای مهندس شهسواری»
   
   الگوی چینش در تنظیمات قابل انتخاب است (`addressee_formats`).
2. `subject` از `letter_type.subject_line` با جایگذاری فیلدها ساخته می‌شود.
3. `body_paragraphs`:
   - پاراگراف‌های `letter_type.body`، با جایگذاری فیلدها و متغیرهای عمومی
   - سپس اگر جدول ردیفی دارد، هر ردیف به شکل «{idx}- {شرح}{ – مقدار}{ – مبلغ ریال}»
   - سپس بندهای انتخابی
   - سپس بند حساب (اگر `with_account`)
4. متغیرهای عمومی در دسترس همه‌ی متن‌ها:
   - `issuer_name`، `issuer_national_id`
   - `customer_name`، `contact_full`
   - `project_title`، `contract_no`، `contract_date`
   - `amount`، `amount_words`، `amount_toman`
   - `iban`، `bank`، `holder`
   - `today`
5. جای‌خالیِ پرنشده نباید در خروجی بماند. پیش از ساخت فایل، فهرست جای‌خالی‌های خالی نشان داده می‌شود.

## ۵.۴ شماره‌گذاری

| صادرکننده | الگوی پیش‌فرض | دامنه | نمونه |
|---|---|---|---|
| COMPANY | `{seq:03}/{yyyy}` | سالانه، جدا برای نامه و برای خانواده‌ی فاکتور | 005/1405 |
| PERSONAL | `{yyy}{mm}{seq:02}` | ماهانه | 405901 |

- توکن‌ها: `{yyyy}` سال کامل، `{yyy}` سه رقم آخر، `{yy}`، `{mm}`، `{seq:0N}`، `{kind}` (ن، پ، ف، ص).
- شماره هنگام **صدور** رزرو می‌شود، نه هنگام پیش‌نویس. پیش‌نویس شماره‌ی «پیشنهادی» نشان می‌دهد.
- شماره‌ی دستی مجاز است ولی تکراری نباید باشد (هشدار).

## ۵.۵ فایل و پوشه

- ریشه: تنظیم `output_root`. پیش‌فرض: `Documents\اسناد پیشگرم`.
- مسیر: `{ریشه}\{نام کوتاه مشتری}\{عنوان پروژه یا «عمومی»}\`
- نام فایل: `{نوع} {نام کوتاه مشتری} {شماره با - به‌جای /} {تاریخ 14050901}.docx`
  - مثال: `پیش‌فاکتور فولاد ناب 014-1405 14050901.docx`
  - نسخه‌های بعدی: ` -v2`، ` -v3`.
- PDF کنار Word با همان نام ساخته می‌شود. PDF ادغام‌شده با پیوست‌ها پسوند ` (کامل)` می‌گیرد.
- کاراکترهای غیرمجاز ویندوز حذف می‌شوند و طول مسیر زیر ۲۰۰ کاراکتر می‌ماند.

## ۵.۶ PDF و پیوست

1. **Word ← PDF:**
   - اولویت ۱: Word نصب‌شده از طریق COM (`docx2pdf` / `pywin32`). خروجی دقیقاً همان است که کاربر در Word می‌بیند.
   - اولویت ۲: `soffice --headless --convert-to pdf` اگر LibreOffice نصب باشد.
   - اگر هیچ‌کدام نبود: فقط Word ساخته می‌شود، با پیام «برای PDF، فایل را در Word باز کنید و Save as PDF بزنید.»
2. **ادغام:** با `pypdf`. هر صفحه‌ی پیوست به اندازه‌ی صفحه‌ی اول سند scale و وسط‌چین می‌شود، با حفظ جهت افقی یا عمودی خود پیوست.
3. **تصویر نقشه** (JPG/PNG) به یک صفحه‌ی PDF با حاشیه‌ی ۱۸pt تبدیل می‌شود.
4. **«پاک کردن ناحیه»:** صفحه‌ی PDF با ۳۰۰dpi رندر می‌شود (`pypdfium2`). کاربر مستطیل می‌کشد، ناحیه سفید می‌شود و صفحه به‌صورت تصویر جایگزین می‌شود. این همان کاری است که برای شناسنامه‌ی نقشه‌ی رهرو ایده رایان انجام شد.
